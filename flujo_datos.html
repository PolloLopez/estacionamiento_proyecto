🅿️ Flujo de Datos — Sistema de Estacionamiento Medido

Conductor Inspector Vendedor Admin Tesorero Sistema automático

Flujo 1 — Estacionamiento (conductor paga solo)

  • 1 Conductor inicia sesión → va a "Estacionar" → elige vehículo + duración
  • 2 Sistema verifica horario activo y saldo suficiente (optimista). Si hay infracción pendiente → aplica tolerancia de gracia.
  • 3 Sistema debita saldo con select_for_update() → crea Estacionamiento(ACTIVO) + MovimientoCaja(ingreso)
  • 4 Conductor ve timer en pantalla. Al vencer: Estacionamiento(FINALIZADO) automáticamente.
  • 5 Si finaliza antes de 30 min → Sistema reintegra 100% del costo al saldo.

Reintegro por cancelación temprana: umbral = 30 min. Lógica en use_cases/finalizar_estacionamiento.py.

Flujo 2 — Cobro manual (inspector/vendedor)

  • 1 Vendedor / Inspector ingresa patente + duración → "Registrar estacionamiento"
  • 2 Sistema crea Estacionamiento(ACTIVO) + MovimientoCaja con comision_monto
  • 3 Se genera ticket de cobro imprimible.

Flujo 3 — Verificación e infracción (inspector en calle)

  • 1 Inspector elige subcuadra → ingresa patente → sistema evalúa:
  • ✅ Exento total → libre  |  ✅ Exento parcial en esta subcuadra → libre  |  ✅ Pago activo o abono mensual → OK  |  ⏳ Verificado hace <15 min → no se puede infraccionar  |  🚨 Resto → INFRACCIONAR
  • 2 Si 🚨 INFRACCIONAR: inspector confirma → sube foto (opcional)
  • 3 Sistema aplica watermark a la foto (patente, inspector, subcuadra, GPS o "sin señal", fecha/hora) vía Cloudinary → crea Infraccion(pendiente)
  • 4 Inspector revisa ticket con foto → hace clic en "Imprimir acta" → después de imprimir redirige a verificar.

Fallback: si Cloudinary falla al subir la foto, la infracción se guarda igual sin foto (no bloquea el acta). Watermark: Pillow, services/infracciones.py::_agregar_marca_de_agua_gps().

Flujo 4 — Pago de infracción

  • A Conductor paga: Conductor → "Mis infracciones" → paga con saldo digital
  • B Vendedor cobra: Vendedor → "Cobrar infracción" → ingresa patente → cobra en efectivo
  • C Al estacionar: Conductor registra estacionamiento → sistema detecta infracción pendiente → aplica gracia

En todos los casos: calcular_estado_tolerancia() decide si anular o cobrar. Dentro de gracia → Infraccion(anulada), sin cobro. Fuera → Infraccion(pagada) + MovimientoCaja.

Flujo 5 — Abono mensual

  • 1 Quien cobra: Vendedor (con comisión) / Admin (100% tesorería) / Conductor (saldo digital)
  • 2 Si el vehículo no existe → Sistema lo crea con get_or_create
  • 3 Crea AbonoMensual (unique por mes/vehículo/municipio) + MovimientoCaja
  • 4 Inspector ve "✅ Abono vigente" al verificar → no puede infraccionar

Flujo 6 — Caja → Rendición → Tesorería

  • 1 Inspector / Vendedor acumula MovimientoCaja durante el turno
  • 2 Al cierre: confirma CierreCaja (ganancia_usuario + monto_municipio). El admin lo recibe.
  • 3 Admin genera Rendicion con desglose efectivo/digital/comisiones para el período → envía al tesorero
  • 4 Tesorero valida (recibida) u observa (con notas) → Rendicion(validada/observada)
  • 5 Tesorero deposita comisión al vendedor → LiquidacionComision(depositada). Vendedor certifica recibo → LiquidacionComision(certificada)
  • 6 Admin puede enviar informe mensual por email (con PDF de infracciones impagas adjunto) a destinatarios configurados en DestinatarioInforme

Flujo 7 — Carga de saldo (MercadoPago)

  • 1 Conductor elige monto → redirige a MercadoPago
  • 2 MP notifica al webhook /mp/webhook/
  • 3 Sistema re-consulta la API de MP con el payment_id → si aprobado: cargar_saldo_conductor() + MovimientoCaja

Admin también puede cargar saldo manualmente con comprobante imprimible.

Flujo 8 — Horarios y días especiales

  • 1 Admin configura HorarioEstacionamiento (por día) y DiaEspecial (feriados)
  • 2 Al intentar estacionar: puede_estacionar_ahora() → DiaEspecial tiene prioridad sobre HorarioEstacionamiento
  • 3 Sistema cierra automáticamente estacionamientos activos cuando vence el horario configurado

Entidades principales y relaciones

Municipio
  • nombre, logo, colores
  • precio_hora
  • comision_vendedor %
  • tolerancia_multa_min
Usuario
  • correo (login), saldo
  • es_admin / inspector / vendedor / conductor / tesorero
  • municipio (FK)
Vehiculo
  • patente (único)
  • tipo: auto/moto
  • exento_global
  • subcuadras_exentas (M2M)
Estacionamiento
  • estado: ACTIVO/FINALIZADO
  • hora_inicio, duracion_horas
  • costo_base, costo_final
  • vehiculo, subcuadra
Infraccion
  • estado: pendiente/pagada/anulada
  • monto, motivo, motivo_anulacion
  • foto → Cloudinary
  • inspector, subcuadra
MovimientoCaja
  • tipo: ingreso/egreso
  • medio_pago: efectivo/mp
  • monto, comision_monto
  • usuario (operador)
CierreCaja
  • ganancia_usuario
  • monto_municipio
  • usuario, fecha
AbonoMensual
  • mes (1er día del mes)
  • vehiculo, municipio
  • vendedor (null si conductor)
  • medio_pago
Rendicion
  • estado: pendiente/validada/observada
  • admin, tesorero
  • efectivo, digital, comisiones, neto
LiquidacionComision
  • pendiente → depositada → certificada
  • vendedor, tesorero
  • monto
Subcuadra
  • calle + altura
  • municipio
Tarifa
  • precio_por_hora (auto/moto)
  • precio_abono (auto/moto)
  • monto_infraccion
