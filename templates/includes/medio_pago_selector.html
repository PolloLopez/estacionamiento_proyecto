{% comment %} Selector de medio de pago — incluir en formularios de confirmación de cobro. Uso: {% include "includes/medio_pago_selector.html" %} El template emite los estilizados como botones dentro del form padre. No necesitás declarar el campo por separado. Selección inicial (prioridad en orden): 1. Si el form viene de un POST (ej: validación fallida), preserva el valor seleccionado gracias a request.POST.medio_pago. 2. Si la vista pasó medio_pago_inicial en el contexto, usa ese valor. 3. Por defecto preselecciona "efectivo". Para forzar otro valor inicial desde la vista: return render(request, "mi_template.html", {"medio_pago_inicial": "transferencia", ...}) NOTA TÉCNICA: No se usa |default:medio_pago_inicial en {% with %} porque Django 5.x/Python 3.12 no atrapa el ValueError que surge al intentar int('medio_pago_inicial') cuando la variable no existe en el contexto. Se usa {% if %} que evalúa variables indefinidas como False de forma segura. Graceful degradation sin JS: - Los labels wrappean los radios: click en el label = click en el radio (HTML nativo). - Sin JS, el radio correcto se envía en el form, pero la clase .medio-activo NO se actualiza visualmente al seleccionar otra opción.
